## 小黑盒第三方桌面客户端（Electron）— 从零搭建完成

**用户需求**：根据 https://xiaoheihe.cn/app/bbs/home 做一个第三方客户端；用户选择 Electron 桌面形态 + 需要 Cookie 登录入口。

### 关键技术成果
1. **逆向并实现小黑盒 Web 端 hkey 签名算法**（`src/hkey.js`）：
   - 字符集 `AB45STUVWZEFGJ6CH01D237IXYPQRKLMN89`（36 位）
   - 时间戳/路径/nonce 三分量分别映射 → 交错混合取前 20 位 → MD5
   - MD5 前 5 位映射（字符集前 32 位）得 hkey 前缀；后 6 字节经 Rijndael 变换求和 %100 得 2 位校验码
   - 测试向量：`/account/data_report_web/` + `1770529394` + `3D6891C5FEBD5A0A4C986784D2F60E81` → `3XX1P62` ✅
   - 算法来源：luckylca 2026-02 逆向博客（旧版 heybox-url 包算法已失效）
   - 零第三方依赖，纯 Node 内置 crypto
2. **接口可用性结论**（重要，避免重复踩坑）：
   - `/bbs/app/feeds`（需 `pull=1`）、`/bbs/app/topic/categories`、`/bbs/app/topic/feeds` ✅ 免登录可用
   - `/bbs/app/link/tree`（详情/评论）→ `show_captcha`，**必须登录 Cookie**
   - `search/v1/web` → `login`，**必须登录**
   - 字段：`link_award_num`=点赞数、`comment_num`=评论数、`up` 恒为 0（是标记不是数量）
3. **踩过的环境坑**：
   - 沙箱注入 `ELECTRON_RUN_AS_NODE=1` → Electron 被降级成纯 Node，`require('electron')` 返回 exe 路径字符串。启动必须 `env -u ELECTRON_RUN_AS_NODE -u NODE_OPTIONS`
   - 沙箱 GPU/渲染子进程全部崩溃（0xC0000005），Electron UI **无法在本沙箱验证**，用户真实桌面无此问题
   - npm install 会卡死在 electron postinstall 下载；手动 `node node_modules/electron/install.js` + `ELECTRON_MIRROR=https://npmmirror.com/mirrors/electron/` 只需 8 秒

## 第二轮：扫码登录 + 打包 exe（23:29-23:45）

### 二维码登录（已实现并实测）
- 接口（复用官方 Web 端公开流程，来源 heybox-cli Go 源码）：
  1. `GET /account/get_qrcode_url/?app=web` → `{qr_url, expire:120}`
     **必须带完整公共参数**（仅最小参数集会返回 failed），qr_url=`.../account/qr_login/?qr=<uuid>&app=web`
  2. `GET /account/qr_state/?app=web&qr=<uuid>` → `result.error`: `wait`/`ready`/`ok`/其他(失效)
     成功时返回 `heybox_id` + `pkey`，据此组装 Cookie
- 二维码图片用 npm `qrcode@1.5.4` 在主进程生成 dataURL（唯一新增运行时依赖）
- UI：登录弹窗 + 状态点（等待/已扫/成功）+ 过期蒙层刷新 + 改用Cookie入口
- 已截图验证弹窗与二维码真实渲染（docs/login-qr.png）

### 打包 exe（成功）
- 产物：`dist/黑盒社区 Setup 1.0.0.exe`（79MB NSIS）、`dist/win-unpacked/黑盒社区.exe`（绿色版 270MB）
- **关键坑 1**：`winCodeSign-2.6.0.7z` 解压失败，因归档内含 macOS 符号链接，Windows 无管理员权限建不了符号链接（报 0x5 客户端没有所需的特权）。
  解法：手动用 7za 预解压到 `%LOCALAPPDATA%/electron-builder/Cache/winCodeSign/winCodeSign-2.6.0` 并 `-xr'!darwin' -xr'!linux'`，electron-builder 检测到目录存在即跳过
- **关键坑 2**：首次 npm install 被中断 → `node_modules/builder-util/node_modules/app-builder-bin/` 只剩 LICENSE 和平台目录、**缺 package.json**，npm 报 `Invalid Version: `（空版本）且删 lock 也无效。
  解法：`rm -rf` 该残缺目录后 `npm install` 即恢复
- 打包会重跑 electron postinstall 清掉 `dist/electron.exe`，需再手动跑一次 `node node_modules/electron/install.js`（8 秒）
- 镜像：`ELECTRON_MIRROR` + `ELECTRON_BUILDER_BINARIES_MIRROR` 指向 npmmirror

### 启动打包后程序的命令（沙箱内）

## 第三轮：修复「二维码登录不可用」（00:00-00:10）

### 排查结论（重要，勿重复排查）
- **用 Edge CDP（remote-debugging-port + Network.getResponseBody）抓到了官方网页版登录的真实响应**：
  `/account/get_qrcode_url/` 返回的 `qr_url` 与本项目生成的**完全一致**
  （`https://api.xiaoheihe.cn/account/qr_login/?qr=<uuid>&app=web`）→ 二维码内容没问题
- 官方 create 参数：`app=web&os_type=web&x_app=heybox_website&x_client_type=web&x_os_type=Windows&client_type=web&web_version=3.0&version=999.0.4`（没有 device_info/device_id/heybox_id；web_version 已是 3.0，本项目用 2.5 也能通）
- 直接浏览器打开 qr_login URL 会 302 到「请登录后使用该功能」错误页（正常现象，App 内扫描才有确认流程）
- SPA 里官方成功后的处理（`e6e()`/`gj()`/`vC()`）：从 **result 响应体**取 `profile.heybox_id||account_detail.userid` + `pkey` 写 document.cookie（heybox_id/user_heybox_id/pkey/user_pkey），**不依赖 Set-Cookie 头**；资料提取也用 account_detail.username/avatar/level_info.level
- 官方校验登录态/拉资料用的是 `/account/restore_login`（未登录返回 status=login）

### 修复内容
1. `src/heybox.js`：新增扫码会话 Cookie 罐（create 起累积，轮询时随请求带上，对齐官方/Go 版 cookiejar）；`buildLoginCookie` 改为官方口径（4 个核心 Cookie + 罐内 Cookie，核心覆盖同名）；新增 `extractProfile`（兼容 profile/account_detail 两种字段）；`getProfile` 改用 `/account/restore_login`（失败才回退旧接口）；轮询网络错误返回 `state:'retry'` 而非直接报错；错误时带 `detail` 原始诊断信息
2. `main.js`/`server.js`：二维码 `margin: 1 → 4`（静区不足是手机扫不上的常见原因）、宽 280→320；登录成功后立即用 restore_login 校验并回传 `warn` 提示
3. `renderer/app.js`：支持 `retry` 状态（连续 6 次失败约 15 秒才报错）、展示 `warn` 与 `detail` 诊断
4. 回归测试 `test/qr-login-test.js`：创建/轮询/失效/字段提取/Cookie 组装全部通过；UI 截图验证正常
